## 1. 这套东西是什么

一条命令在 VPS 上部署 **Xray（XHTTP 传输）+ Nginx（编译版）+ Let's Encrypt 双域名证书**，产出 5 种模式的代理节点和 3 条订阅链接。核心卖点是**上下行分离**：上行/下行可以分别走 CDN 或 Reality 直连，兼顾速度与抗封锁。

**当前版本的主要能力：**
- **vlessenc 强制**（ML-KEM-768 后量子加密，防 CDN 中间人）
- Xray 可选择保留当前版本、最新稳定版、最新预发布版或指定版本
- 服务端 routing 默认**禁 BT / 禁广告 / 禁回国 / 禁私网**
- **geodata 自动更新**（每周一 04:00 cron，失败自动回滚）
- **内置卸载**（`bash install.sh uninstall [-y]`）
- 新增**无域名 Reality 变体**（借第三方网站 TLS，零域名零证书）
- **2026-09-19 安全审计修复**（见第 12 节）

**dist 产物（当前）：**
| 文件 | 作用 |
|---|---|
| `install-xpadding.sh` | 主脚本（xpadding，ECH/FinalMask 可选，**推荐**） |
| `install.sh` | 精简版（不带 xpadding 特性） |
| `install-xhttp-reality.sh` | 无域名独立版（借第三方站 TLS，未真机实测） |
| `add-xhttp-reality.sh` | 扩展：给已有部署追加借证 reality 节点（默认 8443 端口） |
| `add-dual-ip.sh` | 扩展：IPv4/IPv6 双腿节点 |
| `add-dual-cdn.sh` | 扩展：上下行使用不同 CDN |
| `add-quic.sh` | 扩展：XHTTP H3/H2-H3 |
| `add-hysteria2.sh` | 扩展：Hysteria2，支持固定端口和端口跳跃 |

## 2. 架构（看懂这张图再动手）

```
                          ┌─────────── VPS ───────────┐
 直连客户端 ──TCP 443──▶ │ Xray 443 入站 (raw+reality)│
                          │  · vision 节点(UUID1)直连  │
                          │  · 其他 → fallback → 8001  │
 CF CDN ──TLS 443──────▶ │   (reality 不匹配→target) │
                          │          ▼                 │
                          │  Nginx 8003 (127.0.0.1,ssl)│
                          │  · /sub/ 订阅目录           │
                          │  · /xhttp_path → grpc ────▶│──▶ Xray 8001 (127.0.0.1, xhttp)
                          │  · / → 回落站(静态/反代)    │    · vlessenc 解密 + xpadding
                          └─────────────────────────────┘
```

**端口拓扑：**
| 端口 | 进程 | 监听 | 作用 |
|---|---|---|---|
| 443 | xray | 0.0.0.0 | 主入站（reality）；vision 直连 + 回落分发 |
| 8001 | xray | **127.0.0.1** | xhttp 入站（vlessenc + xpadding），所有 xhttp 流量终点 |
| 8003 | nginx | **127.0.0.1**（审计修复后） | 订阅目录 + 回落站 + CDN 回源 grpc 中转 |
| 80 | nginx | 0.0.0.0 | http→https 跳转（acme 申请证书也要用） |

**关键认知**：所有 xhttp 节点（不管直连还是 CDN 腿）最终都落在 **8001**，而 8001 强制 **vlessenc + xpadding**——这决定了客户端兼容性（见第 6、7 节）。

## 3. 前置条件

**系统**：Debian 12+ / Ubuntu 24.04（推荐）；也支持 CentOS/RHEL/Alma/Rocky/Fedora/openSUSE/SLES/Alpine。最低 1C1G（编译 Nginx 时 1G 内存要约 5-10 分钟，属正常）。

**Cloudflare 面板（动手前必须完成）：**
| # | 位置 | 设置 |
|---|---|---|
| 1 | DNS | Reality 域名 → **仅 DNS（灰云）** |
| 2 | DNS | CDN 域名 → **代理开启（橙云）** |
| 3 | SSL/TLS → Overview | **Full (Strict)** |
| 4 | Network | **gRPC 开启** |
| 5 | Edge Certificates | TLS 1.3 开启（默认开） |
| 6 | Edge Certificates | （可选）ECH 开启——仅当你要用 ECH |

**VPS 防火墙**：脚本**不碰防火墙**。安全组/ufw 需自行放行 **80、443**（UDP 443 仅 H3 扩展需要）。

**域名要求**：两个域名都托管在 Cloudflare，且**不能相同**。

## 4. 安装

### 4.1 交互式（标准）
```bash
sudo -i
bash <(curl -sSL https://github.com/hear2one/xy/releases/latest/download/install-xpadding.sh)
# 或用本仓库构建产物
bash dist/install-xpadding.sh
```

**交互问题清单（顺序 + 默认值 + 影响）：**
| # | 问题 | 默认 | 影响什么 |
|---|---|---|---|
| 1 | Reality 域名 | 无 | 直连节点 SNI、订阅链接域名、证书 |
| 2 | CDN 域名 | 无 | CDN 节点地址、证书（两域不能相同） |
| 3 | IP 类型 | 1 (IPv4) | 节点地址取 VPS v4/v6 |
| 4 | 回落方式 | 1 (静态页) | 选 2 则反代真实网站（伪装更真） |
| 4a | （选2）Reality 回落站 | stanford.edu | 反代目标，建议 VPS 当地大学官网 |
| 4b | （选2）CDN 回落站 | harvard.edu | 同上，不能与 Reality 回落站相同 |
| 5 | xpadding Header | Referer | 填充参数放在哪个 HTTP 头里 |
| 6 | xpadding 参数名 | x_padding | 填充参数名 |
| 7 | 启用 CDN ECH | N | 开则客户端需 DoH DNS（见第 7 节） |
| 8 | geodata 自动更新 | Y | 每周一 04:00 更新 geoip/geosite |
| 9 | 服务端 FinalMask | N | 仅写入服务端 XHTTP 入站 |
| 10 | Xray 版本策略 | 新装稳定版；已安装则保留 | 可选稳定版、预发布版或指定 `vX.Y.Z` |

> 选静态回落时，脚本会在 `/var/www/dist/<域名>/index.html` 生成占位页并**暂停等你上传真实页面**（SingleFile 抓取一个真实网站存成单文件 HTML 最像）。确认页面就位后按 Enter 继续。

### 4.2 printf 管道免交互
```bash
printf 'reality.example.com\ncdn.example.com\n1\n1\n\n\n\nn\ny\nn\n\n' | bash dist/install-xpadding.sh
```
依次为 Reality 域、CDN 域、IP 类型、回落方式、静态页确认、xpadding Header、xpadding Key、ECH、geodata、FinalMask，最后一个空行表示使用默认 Xray 策略。无人值守也可使用 `XRAY_VERSION_MODE=stable|beta|version|keep`；指定版本时同时设置 `XRAY_VERSION=v26.9.9`，设置后不会再询问 Xray 版本。
> 空行 = 用默认值。多余输入无害。问题顺序以当前 dist 为准，改动前先 `grep -n 'read -rp' dist/install-xpadding.sh` 核对。

### 4.3 远程非 root（sudoer）跑法
用 askpass 机制，**不要用 `echo 密码 | sudo -S` 链式多条**（stdin 只喂第一个 sudo）：
```bash
# askpass 脚本必须 chmod 755（sudo 以调用者身份执行它）
printf '#!/bin/sh\necho "你的sudo密码"\n' > /usr/local/sbin/askpass.sh && chmod 755 /usr/local/sbin/askpass.sh
printf '域1\n域2\n1\n1\n\n\n\nn\ny\nn\n\n' | SUDO_ASKPASS=/usr/local/sbin/askpass.sh sudo -A bash dist/install-xpadding.sh
```

### 4.4 装完必做（手动，一次）
**CF 缓存绕过规则**（不做的话 CDN 会缓存 XHTTP 响应，时通时断）：
```
Cloudflare → Caching → Cache Rules → Create Rule
表达式: (http.host eq "你的CDN域名") or (http.request.uri.path contains "/你的xhttp路径")
Cache eligibility: Bypass cache → Deploy
```
脚本结尾会打印这条表达式，直接抄。

## 6. 五种节点模式怎么选

| 节点 | 路径 | 速度 | 抗封 | 适用 |
|---|---|---|---|---|
| **reality+vision 直连** | 直连 VPS | ⭐⭐⭐⭐⭐ | ⭐⭐ | VPS IP 未被封时日常主力；**唯一全客户端通用** |
| **xhttp+Reality 上下行不分离** | 直连 VPS | ⭐⭐⭐⭐½ | ⭐⭐⭐ | stream-one 复用，单连接最优 |
| **上行 CDN + 下行 Reality** | 上行经 CF，下行直连 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | **推荐平衡款**：下载不走 CDN |
| **xhttp+TLS+H2（双向 CDN）** | 双向经 CF | ⭐⭐⭐ | ⭐⭐⭐⭐ | VPS IP 已被封/被限速时 |
| **上行 Reality + 下行 CDN** | 上行直连，下行经 CF | ⭐⭐⭐½ | ⭐⭐⭐⭐ | 欧洲 VPS 直连下行差时（下载走 CF 反而快） |

**客户端兼容性（硬约束，2026-09 实测结论）：**
| 客户端 | 内核 | vision 直连 | xhttp 全部节点 |
|---|---|---|---|
| v2rayN / v2rayNG（新版） | xray | ✅ | ✅ 唯一完整支持（含分离/xpadding/vlessenc） |
| mihomo（Clash Verge 等） | mihomo | ✅ | ✅（yaml 已带双腿 xpadding 配置） |
| Streisand | sing-box | ✅ | ❌ 不支持 vlessenc+xpadding |
| 小火箭 / Anywhere | 自研 | ✅ | ❌ 同上 |

> **8001 强制 vlessenc+xpadding = 所有 xhttp 节点只有 xray/mihomo 系能用。** 手机端（iOS 三件套）只用 vision 直连，别在手机上测 xhttp 链接。

## 7. 各客户端使用要点

### v2rayN / v2rayNG（xray 内核）
1. 用**订阅链接**导入（见第 8 节），或粘贴 `client-config.txt` 里的原始 URI
2. ⚠️ **导入后不要"复制分享链接"再导回**——客户端重导出会阉割 URI 里 `downloadSettings` 的嵌套 extra（下行腿 xpadding/xmux 丢失）→ 分离节点下行必挂。已踩过此坑：**以订阅原始行为准，别二次导出**
3. 验证内核是否保留分离配置：导入后检查节点 JSON 里 `downloadSettings.xhttpSettings.extra` 是否还在

### mihomo（Clash Verge / mihomo party）
- 完整分流：订阅 `mihomo-full.yaml`（自带 DNS/规则/策略组）
- 合入已有配置：订阅 `mihomo-nodes.yaml`（纯 proxies）
- mihomo 的 xhttp 键名与 xray 不同（`xhttp-opts`/`ech-opts`/`reuse-settings`），yaml 已按 mihomo 语法生成，别手改成 xray 风格

### ECH 启用时
- 客户端 DNS **必须用 DoH**（223.5.5.5 / doh.pub），否则 ECH 公钥取不到，静默失败
- 外层 SNI 变为 `cloudflare-ech.com`，与优选域名/IP 无冲突

### DNS（mihomo full 已内置，手动配置时注意）
- `proxy-server-nameserver` 必须国内 DoH（223.5.5.5/doh.pub），**不要用 1.1.1.1/8.8.8.8**（解析出的是非优化 IP）

## 8. 订阅链接

三条（都在 **Reality 域名**下，token 为 32 位 hex 路径）：
```
https://<Reality域名>/sub/<token>/v2rayn.txt        # v2rayN（base64 整包）
https://<Reality域名>/sub/<token>/mihomo-full.yaml  # mihomo 完整
https://<Reality域名>/sub/<token>/mihomo-nodes.yaml # mihomo 纯节点
```
- 原始明文行在服务器 `/usr/local/nginx/html/sub/<token>/v2rayn-raw.txt`（v2rayn.txt 是它的 base64）
- **token 泄露 = 订阅泄露**（含全部节点参数）。换 token：删 `/etc/xhttp-cdn/sub_token` 后重新生成订阅目录，或手动改目录名
- 订阅目录有 `no-store` 缓存头 + try_files =404，无目录列表

## 10. 卸载

```bash
bash dist/install-xpadding.sh uninstall      # 交互确认
bash dist/install-xpadding.sh uninstall -y   # 免交互
```
**会删**：xray/nginx/hysteria 服务与二进制、acme.sh 与证书、geodata cron 与更新脚本、`/etc/xhttp-cdn`、客户端配置与订阅文件、acme 相关 crontab 行、gai.conf 里本脚本加的那一行。
**不删**：`/var/www/dist`（可能含你的自定义页面，只提示）。
> 卸载脚本幂等，可重跑。重跑安装也是幂等的（复用证书/跳过编译/复用 sub token）。

## 11. 运维

**证书续期**：acme.sh cron 自动续期，reloadcmd = 重启 nginx（只重载 nginx；若后续加了 hy2，需手动给 hy2 也配置证书重载）。

**geodata 周更**：每周一 04:00，下载 → 非空检查 → 使用候选数据执行 `xray -test` → 本次临时备份 → 替换 → 重启 Xray；验证或重启失败会恢复本次备份。手动运行：`/usr/local/bin/xhttp-cdn-update-geodata.sh`。

**Xray 内核升级/切换**：重新运行主安装器并选择保留、稳定版、预发布版或指定版本，也可以非交互运行：
```bash
XRAY_VERSION_MODE=stable bash dist/install-xpadding.sh
XRAY_VERSION_MODE=beta bash dist/install-xpadding.sh
XRAY_VERSION_MODE=version XRAY_VERSION=v26.9.9 bash dist/install-xpadding.sh
```

REALITY 的 `minClientVer` 按官方定义是可选的最低客户端版本限制。本项目默认不设置，避免误拒绝 Mihomo 或旧 Xray 客户端；只有明确需要强制最低客户端版本时才手动添加。

**改配置**：改完 `xray -test` 验证再 `systemctl restart xray`；nginx 改完 `nginx -t` 再 `systemctl reload nginx`。

**备份关键物**：`/usr/local/etc/xray/config.json`（私钥）、`/etc/ssl/private/`（证书，root 600）、`/etc/xhttp-cdn/`、`/etc/nginx/nginx.conf`。

## 13. 故障速查

| 症状 | 根因 | 处置 |
|---|---|---|
| 订阅链接 404 | /sub/ 路径或 token 错 | 核对 `/usr/local/nginx/html/sub/` 实际目录名 |
| CDN 腿挂、Reality 腿通 | ①CF 缓存规则没建 ②下行腿缺 xpadding（URI 被重导出阉割）③8001 vlessenc 不配 | 按 4.4 建缓存规则；用订阅原始行；对 config.json 8001 decryption |
| 分离节点下行必挂（v2rayN） | 客户端重导出丢了 downloadSettings 嵌套 extra | 从订阅原始行重新导入，别二次导出 |
| 手机端 xhttp 全挂 | 非 xray 内核不支持 vlessenc+xpadding | 用 vision 直连，别折腾 |
| Mihomo 报 `REALITY authentication failed` | 客户端参数、内核能力或服务端手工设置的 `minClientVer` 不匹配 | 默认配置不限制 `minClientVer`；核对 SNI、密钥、Short ID，并移除不必要的版本下限 |
| ECH 开了连不上 | 客户端 DNS 非 DoH | DNS 改 223.5.5.5/doh.pub |
| 证书申请失败 | 80 被占 / 橙云未生效 | 80 空闲检查；`dig @1.1.1.1 域名` 验证橙云（国内 DNS 有旧缓存） |
| H3 节点全挂（扩展） | VPS 外部 UDP 入向被丢（机房/GFW） | 先实测 UDP 443；不通则 H3 直连无解，腿改走 CDN |
| dual-ip 扩展后订阅自检失败 | 443 入站 listen 被改成 "::" 致 IPv4 回环不可达 | `sed -i 's/"listen": "::"/"listen": "0.0.0.0"/' config.json && systemctl restart xray` |
| nginx 报 conflicting server name 8003 | dual-ip 域名与主域名重复/重跑残留 | 同名 server 块去重（新版扩展已修，重跑即可） |
| 编译 nginx 卡 10 分钟 | 1G 内存正常速度 | 等，别 Ctrl+C |
| 回落方式选反代后网站打不开 | 回落站不可达/证书不匹配 | 换 VPS 当地大学官网；别用 CF 站与烂大街站 |
| `xray vlessenc` 报错 | 内核太旧不支持 | 重跑安装器，选择满足要求的稳定版、预发布版或指定版本（见 11 节） |
| 换 VPS 后节点全挂 | 密钥/IP 全变 | 属正常，重新部署；旧备份在 ~/vps156-backups/ |
