# 代码审查记录（2026-09-09）

## 范围

检查了模块化 Bash 安装流程、配置模板、扩展构建和 GitHub 发布工作流。本次修改保留原有部署方式，重点修正可从代码确定的问题。未连接或修改 VPS。

## 已修复

| 问题 | 影响 | 修改 |
| --- | --- | --- |
| 回落 URL 仅提取任意 authority，未限制空白、分号等字符 | 输入直接写入 Nginx 指令，可能导致配置损坏或注入额外指令 | 主脚本及三个使用相同函数的扩展改用共享校验，拒绝用户信息、非法主机、非法端口和空白 |
| 主脚本域名、IP 选择和 xpadding 参数校验不足 | 无效值进入路径、JSON/YAML 或后续分支 | 校验域名标签和长度，忽略大小写判断重复域名；IP 仅允许 1/2；padding 仅允许字母、数字、下划线及连字符 |
| geodata 被要求包含 ZIP 的 PK 文件头 | 正常 Protobuf 数据无法通过更新检查 | 下载后由 Xray 使用候选 asset 目录测试当前配置，通过后才替换 |
| 更新回滚只处理 systemd 重启失败，备份错误被忽略 | OpenRC 重启失败后保留新数据，或回滚到遗留备份 | 替换前确保两份备份成功；替换错误和两种服务管理器重启失败均恢复本次备份 |
| 发布流程未构建及上传两个 Reality 入口 | 对应安装文件无法随 release 发布 | 增加独立安装与扩展的构建、上传和发布 |
| 独立 Reality 构建未创建输出目录 | 全新输出路径构建失败 | 写入前创建输出目录 |
| 缺少自动构建检查 | 模板残留或 Bash 语法错误可能进入 release | 普通推送、PR 与发布运行统一检查脚本 |

geodata 格式依据：[Xray 官方数据定义](https://github.com/XTLS/Xray-core/blob/main/common/geodata/geodat.proto)及[官方加载代码](https://github.com/XTLS/Xray-core/blob/main/common/geodata/geodat_loader.go)。

回落 URL 校验支持 DNS 主机名、IPv4 形式的主机及可选端口；路径、查询和片段继续按原行为舍弃。不支持用户信息或 IPv6 字面量。候选数据检查验证当前 Xray 配置引用的规则，不等于检查数据文件内所有记录。

## 验证

- 全部 7 个构建入口生成 8 个脚本，均通过 `bash -n`，没有残留 `@@include`。
- 输入回归覆盖有效主机、路径归一化、端口边界、空白、换行、分号、用户信息和非 HTTP 协议。
- geodata 测试隔离网络和服务命令，在临时目录分别模拟 systemd/OpenRC 的正常更新、候选数据不通过验证、首次重启失败后回滚，共 6 种场景。
- 本地使用 Windows Git Bash 运行。模拟测试不证明真实 Xray/Nginx、证书续期或 CDN 链路在 VPS 上工作正常。

## 仍需后续改进

- 主安装流程直接覆盖 Nginx/Xray 配置，缺少贯穿整个部署的备份与失败恢复；在生产 VPS 上重跑前仍应保存现有配置。
- 上游安装脚本及版本获取依赖在线远程内容，尚未统一固定版本并校验下载摘要。
- 最终输出含私钥和订阅凭据，应避免把终端输出、客户端文件或二维码提交到公开仓库。
- geodata 更新尚未添加并发锁；应避免手动更新与定时任务同时运行。
- 当前修改没有完成实际 Linux 发行版矩阵、证书签发、Nginx 配置加载及各客户端的端到端连通测试。
